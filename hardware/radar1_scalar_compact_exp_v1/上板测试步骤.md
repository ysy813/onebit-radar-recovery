# 实验部署上板操作

## 1. 准备

使用正点原子MPSoC 4EV，连接JTAG、串口（原工程使用的COM口，115200/8N1）和HDMI。雷达/DCA1000沿用之前验证的1024 ADC点、512chirp、4RX及原500ms周期配置，网线仍接PL网口。上电前先停止雷达数据流。

只使用本目录 `pkg` 中配套BIT/ELF。先确认 `pkg/BUILD_READY.json` 的 `ready_for_board_test=true`。无需更换SD里的 `SAR_DESC.BIN`，本架构不用该描述符；纯成像测试不要求SD卡，存储测试需有足够空间的原FAT卡，不要格式化或删除已有数据。

## 2. 先测试网络成像

打开串口并开始保存完整日志，然后在PowerShell执行：

```powershell
Set-Location 'C:\Users\yang\Desktop\SAR_IMAGE\radar1_scalar_compact_exp_v1'
& 'C:\Xilinx\Vitis\2022.1\bin\xsct.bat' '.\pkg\program_onebit_network.tcl'
```

该脚本会复位FPGA/PS、下载本版BIT和网络ELF。等待串口 `IMAGING_INIT_PASS`、`NETWORK_REQUEST=1, scalar-compact-exp-v1`，且没有 `FAIL`。HDMI仍是720p60，先有显示背景/计数，生成雷达图像需要等待整帧处理。

按一次PL_KEY2（按住超过50ms），等待5秒。mmWave Studio按原流程点击DCA1000的Arm后Trigger Frame。持续采集，等待 `NET` 中 `done` 至少增加2–3次；不能只按原500ms周期判断网络是否完成。

保存完整串口输出到 `board_runs/network.txt`，包括启动和结束，不仅是Stop之后的内容。正常条件：`enabled=1`、`done`持续增加、`fault=0`，显示图像有更新。`image_skip`增加表示成像忙时按完整帧跳过，不等于原始SD丢数据。`infer_ms`是一次网络计算时间，不能当显示帧周期。HLS估计网络约2.96秒/帧，实际还包含DDR等待及FFT/插值时间；屏幕整数FPS可能一直显示000，要结合done和画面更新判断。

先Stop Frame，等当前网络/插值完成、busy回到0，再切换模式。最后一幅画面停留是正常行为。

## 3. 单比特旁路对照

停止雷达后执行：

```powershell
& 'C:\Xilinx\Vitis\2022.1\bin\xsct.bat' '.\pkg\program_onebit_bypass.tcl'
```

重新按PL_KEY2、Arm、Trigger，保持场景、雷达参数、增益和显示设置相同，日志存 `board_runs/bypass.txt`。本轮 `NETWORK_REQUEST=0`，网络done不增加属正常。观察同一静态场景的目标可见性、谐波/条纹及背景变化；动态目标两次采集不是真正同一帧，不能仅据画面断言真目标保留。严格同帧对照仍以PC原始BIN重放分析为准。

如需原多比特参考，在停止雷达后用 `pkg/program_raw_imaging.tcl`，再按相同启动流程。

## 4. 网络成像加原始数据存储

完成前两项后，插入SD卡，停止雷达，执行：

```powershell
& 'C:\Xilinx\Vitis\2022.1\bin\xsct.bat' '.\pkg\program_onebit_network_storage.tcl'
```

确认串口SD挂载及DMA初始化成功，再按PL_KEY2、Arm和Trigger。日志存 `board_runs/network_storage.txt`。SD保存原始RX0的ADC，网络输出不写入这些BIN。完成采集后先Stop Frame；程序在收到数据后连续5秒没有新完整块时开始结束和回读校验，等待最终 `RESULT` 和文件关闭，再断电/取卡。SD速度仍受原卡和文件系统限制。
