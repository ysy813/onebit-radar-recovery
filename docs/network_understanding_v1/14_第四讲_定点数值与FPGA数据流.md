# 第四讲：同一个网络怎样变成FPGA里的整数电路

本讲把实数公式、PC整数参考、HLS数值IP和整机调度对应起来。当前模型与工程均冻结，没有训练、重新综合或板卡访问。

先记住三层分工：**MLP的数学结构决定计算什么，定点格式决定怎样表示数值，帧控制与DDR组织决定何时计算和读写哪里。** 三者不能混成“放入一个IP就自动实时”。

## 1. Q12、Q16、Q14到底是什么

本文Qn仅表示整数带n位二进制小数缩放，不默认总位宽或符号类型。若存储整数为q，其代表的实数为：

$$v=q/2^n.$$

| 数值 | 当前整数容器 | 小数缩放 | 例子或原因 |
|---|---|---|---|
| 基础特征z等 | 13位无符号 | Q12 | 4096代表1，12位无符号容器放不下4096 |
| 展开特征、激活与分数 | 32位有符号 | Q16 | 65536代表1；关系特征与最后分数可以为负 |
| 神经权重 | 20位有符号有效表示 | Q16 | 范围约−8至8，不能用纯16位容器代替 |
| 偏置常量 | C源码long long；加入48位累加器 | Q32 | 与两个Q16数的乘积对齐 |
| 神经乘加和 | 48位有符号 | Q32 | 给多项求和及符号留出空间 |
| 最后分数的查表坐标 | 整数下标计算 | Q10 | 从Q16舍去6位小数后查询exp2表 |
| 幅值增益 | 16位无符号容器 | Q14 | 16384代表1，2048代表0.125 |
| FFT输入/输出功率 | 64位无符号 | 原功率单位 | 没有把功率缓存改成RGB |

例如特征整数3006是3006/4096≈0.733887。进入Q16运算时左移4位得到48096，48096/65536仍是同一个值。**左移改变缩放，不会补回原来已经量化丢失的信息。**

当前提高内部精度，是减少五次方、关系项、乘加和输出换算的额外数值误差；不等于输入又多出了新的雷达观测信息。

## 2. 浮点权重怎样成为HLS常量

当前采用冻结浮点参数的定点导出，没有进行量化感知再训练：

$$W_q=\operatorname{round}(2^{16}W),\qquad b_q=\operatorname{round}(2^{32}b).$$

导出使用NumPy rint的舍入规则。当前已逐项核对：浮点检查点按该式导出，与PC weights.npz及HLS parameters.h中的W0/W1/W2、B0/B1/B2一致；ROOT5与GAIN表也逐项一致。

实际权重整数范围为−328382至252284，都能放进20位有符号范围。这里“能够放进”是对当前冻结系数的检查，不表示以后随便换权重仍能沿用原位宽结论。

固定参数被综合进IP与BIT，**当前板端不是每帧从SD卡加载weights.npz，也没有运行Python/PyTorch。** AQ/AR是插值映射参数，DDR work区是中间数据，二者均不是这1857个神经参数的另一种叫法。

例化过程是：HLS C/C++描述整数计算 → HLS生成RTL并导出IP目录 → BD实例scalar_gain_0连接时钟、AXI和启动/完成 → 整机综合与布局布线生成BIT。配套PS软件生成ELF，负责系统初始化和管理。HLS源文件采用C++语法，不表示这些循环由PS的CPU执行。

## 3. 一层乘加为什么要先扩大，再右移

两个Q16整数相乘，整数乘积代表Q32数；因此偏置也采用Q32。第j个神经元计算：

$$t_j=b_{q,j}+\sum_k W_{q,jk}a_{q,k},$$
$$a'_{q,j}=\operatorname{ReLU}\left(\left\lfloor\frac{t_j+32768}{65536}\right\rfloor\right).$$

前两层有ReLU，最后一层没有。右移16位将Q32变回Q16，32768是半个被舍去的整数单位，用于最近舍入。算术右移在这里对应带符号的向下取整。

这不是所有舍入都使用同一个规则：当前乘加采用“加半后右移”，恰好半格时向正方向；系数导出的rint使用另一种平局规则。必须复现实际代码，而不是笼统说“所有地方都四舍五入”。

例如被右移整数t为−32768，计算(t+32768)>>16得到0；t为32768则得到1。这里的0/1是输出激活的整数格，不是说物理幅值只有0或1。

HLS先把参与乘加的数放到足够宽的类型中。若先在窄位宽溢出，再转成48位，错误已经发生，无法靠后续扩位挽救。

## 4. 真正展开一个已有点

以自然索引(200,148)为例，第一层第0神经元：

| 项目 | 当前数值 |
|---|---:|
| 第0输入Q16 | 26672 |
| 对应权重Q16 | −1468 |
| 这一项乘积Q32 | −39154496 |
| 神经元偏置Q32 | −1031898112 |
| 全部40项乘积加偏置Q32 | 45230975 |
| 舍入后激活Q16 | 690 |
| 解码激活 | 690/65536≈0.01052856 |

一个神经元得到690，不代表“目标存在概率1.05%”。它只是中间激活，还要与其它31个激活一起送入下一层。

该点经过32→16→1后，最后分数整数为−78473，即s≈−1.197403。转为Q10：

$$s_{q10}=(-78473+32)\gg6=-1226.$$

查表下标为−1226+16384=15158，GAIN[15158]=7145，因此原幅值增益7145/16384≈0.436096。随后按第三讲的两层保护，变成14022，再变成16384。

这条计算链把“浮点公式中的增益”“整数7145”和“板端功率修改”联系起来。4个已有点的所有32/16/1层激活与原发布记录逐项一致，不是重新训练出的新结果。

## 5. exp2和五次根为什么查表

MLP的矩阵乘加、ReLU适合整数电路，但幂函数不必为每个点实现一套通用浮点运算。

- ROOT5表将16位归一化幅值下标映射为Q12五次根编码。
- GAIN表将Q10分数坐标映射为Q14有界幅值增益。

当前GAIN有32769项，对应分数坐标−16至16；表内已经包含−3至log2(1.5)的增益头限幅。查表下标也被限制在合法范围。因此表两端不会允许极端分数生成无限大或零增益。

平方根采用整数算法：

$$u_i=\lfloor\sqrt{P_i2^{16}}\rfloor,\quad U=\lfloor\sqrt{P_{max}2^{16}}\rfloor,$$
$$n_i=\left\lfloor\frac{65535u_i+\lfloor U/2\rfloor}{U}\right\rfloor,\quad z_i=ROOT5[n_i].$$

u约等于256倍幅值，再按帧最大值归一化。非零帧这样计算；全零帧在峰值扫描后直接返回，功率保持零。

**1857只统计可训练的权重和偏置，不统计查表、行缓存、远程关联支持和DDR工作区。** 因此参数少不等于存储资源几乎不占用。

## 6. 为什么48位累加器有依据

基础Q12特征限制在0～4096。展开到Q16后，大部分输入在0～65536；第13～15项关系特征允许负值。对每个神经元可用三角不等式给出保守界：

$$|t|\le|b_q|+\sum_k|W_{q,k}|\max(|a_{q,k}^{min}|,|a_{q,k}^{max}|).$$

该界包住全部部分和，因此也覆盖HLS可能进行的加法重排。逐层传播区间得到：

| 层 | 累加所需有符号位数上界 | 当前采用 |
|---|---:|---:|
| 40→32 | 38 | 48 |
| 32→16 | 41 | 48 |
| 16→1 | 41 | 48 |

舍入常数也在当前48位余量内；逐层输出在32位有符号范围内。这些界针对冻结系数和规定特征范围，不假定所有组合都来自真实场景，因而较保守。

隐藏激活可以大于1，不能因为输入归一化到1，就把所有中间值都放进只有符号和小数位的窄容器。

这是**不溢出的数值依据**，不能扩写成恢复正确、泛化可靠或整机时序完整通过的证明。

## 7. 为什么功率写回需要96位临时数

g_q14表示幅值增益，两个相乘带28位小数。因此：

$$P_{out}=\operatorname{sat}_{u64}\left(\frac{P_{in}g_{q14}^2+2^{27}}{2^{28}}\text{向下取整}\right).$$

g=1时g_q14=16384=2^14，乘其平方后右移28位，得到原功率。g=0.5时功率约变为1/4。

已有被衰减点(774,511)的P=58344130412905，最终g_q14=2048，即幅值1/8、功率1/64。舍入后写回911627037702，与已有输出一致。

P可以占满64位，最大增益为24576。最坏乘法加舍入项需要94位无符号整数，当前HLS使用96位临时数，再右移、检查并饱和到uint64。不能先用64位乘到溢出，再指望最后饱和修复。

## 8. PC自然索引为什么与板上DDR列不同

PC特征按自然Doppler顺序处理；板端原功率缓存的列已经shift了256。HLS使用：

$$a_{DDR}=a_{natural}\mathbin{\mathrm{XOR}}256,$$
$$\mathrm{addr}=0x24000000+8(512r+a_{DDR}).$$

对512列而言，这等价于加256后模512，两次转换回到原列。只转换列，不转换距离行。

| 自然列a | DDR列 |
|---:|---:|
| 0 | 256 |
| 148 | 404 |
| 255 | 511 |
| 256 | 0 |
| 511 | 255 |

特征、三/五次关联和周期邻域在自然索引中构造；读取原功率与最后写回时转换。若在shift后的列上直接做−3/+5倍频关系，查询位置就会错误。

## 9. 网络真实插在哪里，为什么图上有模块在FFT前

BD里有三种不同角色：

| 模块 | 位置与职责 |
|---|---|
| network_frame_control_0 | FFT前的帧准入与完成调度，透传或整帧跳过I/Q |
| image_preprocess_0 | FFT前的数字I/Q符号量化 |
| scalar_gain_0 | FFT功率写完后，通过AXI主接口读写DDR并执行网络 |

实际连接已经从当前BD核对：network_frame_control_0/m_axis_tdata接image_preprocess_0/s_axis_tdata；后者的m_axis_tdata接xfft_0/s_axis_data_tdata。这条FFT前的线传的是I/Q，**不是网络处理后的功率**。

scalar_gain_0另有m_axi_mem接口，power和work两个指针共用这个AXI bundle。功率基址为0x24000000，工作区基址为0x31000000，经互连访问DDR；它不通过上面的I/Q流线输出RGB。

因此网络的数值顺序仍是：原二维FFT写功率 → scalar_gain读写功率 → 原AQ/AR插值 → 显示。不能只根据BD中模块框的位置判断算法执行先后。

## 10. 为什么要分多遍处理整帧

一帧功率是1024×512×8字节=4MiB。工作区为16MiB，逻辑划成4个各4MiB区域。

| 阶段 | 主要读什么 | 生成或修改什么 |
|---|---|---|
| PEAK | 原FFT功率 | 帧峰值 |
| NORMALIZE | 原功率、帧峰值 | work第0区的自然顺序z |
| STATS | z及行缓存 | 第1区打包4项统计；片内父查询支持表 |
| SCORE | z | 第2区的子关联门控分数 |
| GATE | 门控分数 | 第3区的3×3门控支持 |
| INFER | 原功率、统计、邻居与关联支持 | 40维→MLP→两层保护；最终增益写第2区 |
| APPLY | 原功率和全部最终增益 | 统一修改原功率缓存 |

SCORE阶段的“分数”是子关联门控中间量，**不是MLP最后的log2增益分数s**。第2区被复用前，所需门控支持已放到第3区。

先算全部增益再写功率，是为了避免逐点处理顺序污染输入：如果处理前一个点就立刻修改功率，后面的局部最大、弱峰判据可能读到已修改值，整帧结果就不再对应同一份原FFT谱。

非局部父子查询需要远程谱点，帧峰归一化又依赖整帧最大值；当前实现因此采用多阶段DDR处理，而不是一个只延迟几行的纯局部流式滤波器。

## 11. 是谁启动网络，为什么PS没有逐点算神经元

当前HLS接口为ap_ctrl_hs启动/完成握手，基址来自BD常量；逐帧启动由PL帧控制器完成，**不是PS每帧发送一组神经元命令**。

| 事件 | 控制器动作 |
|---|---|
| 空闲时遇到新帧首个有效传输 | 接纳整帧，置busy |
| fftshift_write报告帧写完 | 若启用网络，发net_start；否则直接启动插值 |
| 网络完成 | 记录网络阶段周期，启动插值 |
| 插值完成信号到达 | 释放busy，允许接纳后续完整帧 |
| busy期间遇到新帧 | 消耗并跳过该成像帧，不把半帧拼入下一帧 |

原始SD分支在上游独立分流。因此最近已有板测可同时出现“存储60块、网络准入6帧、完成6帧、成像跳过54帧”。这不表示网络计算了60帧，也不表示雷达停止后有54个成像任务在排队。

网络是否启用在首次传输时锁定；当前不是按键随时热切换模式的设计。本讲只解释冻结实现，不改模式逻辑。

PS负责初始化、模式配置、SD存储管理和日志等工作。它没有执行当前40→32→16→1乘加，也不会在板上反向传播更新权重。

## 12. 两个时钟域与三种时间

当前BD确认：

- scalar_gain_0运行于100MHz，即10ns/周期。
- network_frame_control_0与网络状态计时运行于250MHz，即4ns/周期。
- network_cdc通过toggle请求/完成握手连接两个域；结果在下一任务前保持稳定供采样。

软件把控制器计数除250000得到整数毫秒。不能拿HLS核心的100MHz去换算该日志计数。

| 数字 | 含义 |
|---|---|
| 295812315周期 | 既有HLS非零整帧最大延时估计 |
| 2.366498520秒 | HLS报告按8ns调度目标换算的时间 |
| 2.958123150秒 | 同周期数按实际100MHz核心换算 |
| 约3.888秒 | 最近板测记录的网络阶段时间，包含握手及实际执行/等待 |

8ns是综合调度目标，为实现留余量，不表示当前BD实际接了125MHz。HLS零帧可在峰值扫描后提前返回，所以报告最小值也不能当作常规非零雷达帧速度。报告中的平均上下界值不等于对真实数据测出的平均性能。

板测与估计的差额不能仅凭总时间分配给某一个瓶颈；AXI等待、互连和访存等会影响实际执行。没有逐阶段实测，不能宣布差额全部来自某项。

infer_ms不包含完整FFT、插值和显示刷新端到端延时。按3.888秒只计算网络阶段，理想连续吞吐约0.257帧/秒；不能称为满足500ms输入的全帧实时恢复。

日志中的done是累计完成网络任务数，infer_ms是最近一次完成任务的计时，不是整个运行期间的平均值。HLS suppressed计数是最终增益<1的谱点数，不是被删除的物理目标数，也不要求这些点的输入功率一定非零。

## 13. 1857个参数为什么仍然慢

一套参数在每个谱点重复使用。每点MLP核心乘加为：

$$40\times32+32\times16+16\times1=1808\ \mathrm{MAC}.$$

整帧为947912704 MAC，约9.48亿次；还没有计入特征、谐波查询、保护、查表与DDR阶段。

HLS对单个输出神经元的输入维展开乘法，对输出神经元循环并流水，再跨谱点复用结构。代码出现PIPELINE II=1，表示对应循环的调度目标，**不是整帧处理顶层每周期输出一个恢复谱点**。

当前整机BRAM119.5/128、URAM43/48、DSP262/728。这是成像、显示、存储与网络的合计，不能把262个DSP都算成MLP，也不能凭DSP未满就直接按比例推算最终帧率。

本讲解释现有架构，不继续进行性能优化或重建工程。

## 14. 当前硬件固定的是哪种有效chirp配置

PC参考支持128/512有效chirp分支；当前scalar_gain HLS接口没有actual_chirps参数，保护按512有效chirp实现，配合当前1024×512输入帧使用。

不能因为PC程序能选择128，就说同一BIT已经自动支持128保护语义。这里记录现有接口边界，没有新增128板测。

## 16. 论文汇报的一段实现说明

> 为适配原功率缓存接口，我们将冻结MLP导出为整数权重：基础特征采用Q12，内部激活采用Q16，神经乘加使用48位累加，输出幅值增益采用Q14。通过查表实现幂次编码与指数增益，并以增益平方修正uint64功率。PL在FFT功率写完后启动网络，先计算全帧增益再统一写回，之后启动原AQ/AR插值。实现核对覆盖系数、定点数值与控制流程；当前采用资源复用和DDR多阶段处理，其板测网络阶段约3.89秒，尚不具备500ms输入下逐帧恢复的实时性。
