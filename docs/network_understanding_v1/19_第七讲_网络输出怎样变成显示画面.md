# 第七讲：网络修改功率后，屏幕为什么会这样显示

当前算法在二维FFT功率域工作；AQ/AR负责按旧整数公式查找功率地址；显示端再抽取像素和转换灰度。论文中应把这三个算子分别讲清，避免把坐标映射或显示变换的现象归给网络。

本讲只读当前工程、原AQ/AR表和已有诊断输出，核对静态地址与计算。没有新FFT、网络推理、训练、构建或板卡访问。下文的屏幕坐标是按代码计算的逻辑坐标，不是本轮用显示器测得的位置或时序对齐结果。

## 1. 当前真正的数据路径

~~~mermaid
flowchart LR

 B --> C[共享MLP及保护]
 C --> D[修正功率写回]
 D --> E[AQ/AR整数坐标查找]
 E --> F[1687×843功率图缓存]
 F --> G[保留偶数行和偶数列]
 G --> H[844×422预览]

~~~

网络改的是谱点功率。坐标查找改的是“哪个图像位置读取哪个谱点”。显示改的是“取到的数怎样变成可见亮度”。三个阶段的输入输出意义不同。

## 2. 旧工程叫“插值”的IP，实际怎样工作

当前interp_ip对一个有效输出像素执行：读取AQ/AR表项，运行CCID_count整数换算，得到xid和yid，再读取一个64位功率字并写入图像缓存。

线性字节偏移是：

$$\mathrm{offset}=8\,(512\,yid+xid).$$

实际部署参数为64位AXI、每次1拍；数据路径将DATA_FIND_out直接写到输出。这里没有读取四邻点并乘双线性权重，也没有神经网络生成坐标。

因此更准确的论文描述是“沿用原AQ/AR整数地址映射与单点重采样”。旧公式包含截位、向上取整及历史偏移，不能直接写成标准最近邻四舍五入。也不能因为模块名叫interp，就把它描述成一般的双线性插值。

AQ/AR表已经作为二进制数据嵌入当前软件，启动时复制到0x23000000。它不属于1857个学习参数。这份radar1链路也不是此前依赖SAR_DESC.BIN的新版工程，两个工程的描述符/坐标接口不能混称。

## 3. 从自然FFT索引到画面，需要两次查找

网络使用自然FFT坐标(r,a)，板端功率缓存的列是a XOR 256，因此自然点地址为：

$$0x24000000+8\,[512r+(a\mathbin{\mathrm{XOR}}256)].$$

输出像素则从自己的AQ/AR表项计算线性地址。保留的旧列进位规则意味着不能简单把所有xid都当作0到511之间的列；应先计算完整线性索引，再检查最终偏移。

当前保护要求偏移小于4MiB并且8字节对齐，1908个原表越界项跳过读取。AR=0的表外像素同样跳过写入。板端保留已初始化的显示字，初始化为UINT64_MAX时灰度是255；离线图用掩码表示这些无效位置，不能把它们算成网络恢复出的背景。

网络覆盖0–1023自然距离索引，但画面仅显示AQ/AR选中的位置。当前静态表的覆盖统计为：

| 项目 | 数量 |
|---|---:|
| 网络功率数组 | 1024×512＝524288点 |
| 原输出图像 | 1687×843＝1422141像素 |
| 表内且功率地址有效的图像像素 | 743611 |
| 被有效图像访问的不同功率位置 | 398999 |
| 一个功率位置被重复访问的最大次数 | 6 |
| 当前720p图像窗口 | 844×422＝356168像素 |
| 窗口内有效地址像素 | 185905 |
| 抽取后访问的不同功率位置 | 174483 |

这些是地址覆盖和重复次数，不是目标数量、可测距离或实测分辨率。某个FFT点被网络修改，不一定在当前预览中有对应像素。

## 4. 当前显示还做了什么

显示DDR读取器保留源图像的偶数行与偶数列，得到844×422预览；它不是对2×2像素求平均。窗口左上角为屏幕(218,149)，因此源图像偶数坐标(row,col)对应逻辑屏幕：

$$x_{screen}=218+col/2,\qquad y_{screen}=149+row/2.$$

抽取可能遗漏一个只出现在被丢弃像素上的细小结构，所以预览不能代替全分辨率数值检查。它也没有让网络少处理FFT点：网络仍然处理原1024×512功率帧。

当前HDMI图像区域用：

$$B(P)=(P\gg24)\ \&\ 255,\qquad RGB=(B,B,B).$$

这是截取功率第31至24位形成灰度，没有归一化、对数转换或饱和限幅。高于31位的信息被丢掉，所以**B(P)不随P单调增加**。

例如输入P=2^32，截出的灰度是0；幅值增益g=0.5使功率下降到2^30，灰度却变为64。功率下降6.02dB，画面可以反而变亮。

## 6. PC对照图怎样避免这个歧义

当前results_compact的图直接显示RD数组：多比特参考按自己的峰值归一化，单比特旁路与两个增强输出共用旁路峰值；再转换为dB、统一−60到0dB，并用turbo伪彩色显示。

对旁路和增强，固定尺度S下有：

$$20\log_{10}\sqrt{P/S}=10\log_{10}(P/S).$$

这个标量随P单调变化；绘图上下限之外会显示同一端点颜色，因此仍需保留数值指标。turbo各RGB通道和人眼亮度并非单调功率计，应按同一色条解读，不能只比较某个颜色通道或肉眼明暗。

同点的理想网络变化为20log10(g)。g=0.125对应约−18.06dB，在统一dB数据中含义明确；不会因为截取某8位而回绕。各输出分别自动拉伸会破坏这种可比性，所以当前对照禁止独立拉伸。

这组图的坐标是自然距离索引与移位Doppler FFT索引，没有经过AQ/AR，也不直接是笛卡尔SAR地图。论文可作为“RD域恢复对照”，应与“旧映射后的成像预览”分别命名。

## 7. 为什么RD指标和映射后的指标可能不同

设固定映射中输出像素j读取输入位置k(j)，那么映射后的幅值误差平方和为：

$$E_{map}=\sum_j|\widehat A_{k(j)}-A_{ref,k(j)}|^2
=\sum_i m_i|\widehat A_i-A_{ref,i}|^2,$$

其中m_i是该谱点被有效图像像素选中的次数。原RD误差每个谱点计一次，映射误差则有未选点和重复点；720p抽取还会再次改变m_i。

举例，两个点的参考幅值为[0.2,0.2]，旁路为[0.3,0.2]，增强为[0.2,0.28]。RD平方误差由0.01降为0.0064；若两点被选中次数为[1,4]，映射误差却由0.01升为0.0256。这是数学示意，说明总体RD改善不能单独推出映射后所有指标都改善，不是本轮发现了新的模型性能下降。

若每个有效点的误差都不增，则固定非负采样次数下的映射误差也不会增加；但当前只证明某些集合和总体指标改善，没有逐点全域不增的保证。

## 8. 为什么把网络放在映射前

三/五次谐波折叠关系是在FFT索引网格中定义的。AQ/AR改变邻域、重复和遗漏谱点，显示又丢掉大量数值信息。先在原功率帧提取特征，可以利用这些原始频谱关系。

对于已经计算好的g，单点取样确实满足：

$$T(P\odot g^2)_j=P_{k(j)}g_{k(j)}^2.$$

可以把这看作同步取样P和g再相乘，但**不代表可以把整个网络移到映射图上重新计算并得到相同g**。网络依赖的FFT邻域与谐波坐标已不同，输入尺寸与信息也变了。当前设计的位置有任务和接口上的依据。

## 9. 功率恢复为什么不能替代相干聚焦

标量P丢掉了复相位。例如两个复数分量分别为[1,1]和[1,−1]时，各分量功率都为[1,1]；相干相加的功率却分别是4和0。只给各分量功率，无法知道应该是哪一种。

所以当前功率网络与功率单点映射不能凭空重新完成未知相位补偿、轨迹校正或相干聚焦。这里是在既有成像链路中改善量化后的幅值结构，而不是宣称网络已修复全部SAR几何问题。RD恢复的数值证据和物理SAR聚焦证据要分别给出。
