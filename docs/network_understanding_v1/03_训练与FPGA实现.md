# 参数怎样训练，算法怎样进入FPGA

## 1. 先把训练和推理分开

训练时同时有两条同源数据：

~~~mermaid
flowchart LR
 X[同一份原始或受控回波] --> M[多比特二维FFT]
 X --> Q[严格I/Q符号量化]
 Q --> B[单比特二维FFT]
 M --> Y[归一化参考幅值y]
 B --> F[输入幅值x与特征f]
 F --> N[MLP预测增益g]
 N --> E[预测幅值 xg]
 E --> L[与y比较的复合损失]
 Y --> L
 L --> U[反向传播与Adam更新参数]
~~~

推理时只需要单比特FFT功率和固定参数，不需要再提供多比特图，也不会在板上做反向传播。

多比特标签是同源数据经过数值FFT后的参考，不是“所有物理目标的精确真值”。真实数据中的杂波、噪声或未知运动仍可能保留在参考中。

## 3. 用了哪些训练数据

所选配置记录62个配对缓存记录：

| 类型 | 数量 | 应怎样理解 |
|---|---:|---|
| 先前受控数据 | 20 | 受控合成或控制目标记录 |
| 旧512chirp历史采集 | 6 | 曾参与开发，不能再称盲测 |
| 新实测通道/排列记录 | 24 | 包含RX0/RX3及两种读取排列；不是24个独立场景 |
| 新增受控合成 | 12 | 用于补充已知目标、谐波与噪声条件 |
| 合计 | 62 | 配对记录数，不是独立真实场景数 |

每个记录按目标、支持峰、伪影、低背景和随机区域有放回抽样22528个点，共1396736个缓存点样本。训练再从池中随机取批次，因此样本数不等于独立观测数。

两条FFT采用一致的位精确数值模型；128有效chirp是在量化后补零到512，不等于采集了512个有效chirp。新BIN按用户确认RX0/RX3使用，chirp内RX分块为主约定，另一排列只作为稳健性检查。

同一源帧的各通道和读取排列应放在同一数据划分，防止明显同帧泄漏。不过同一次采集的不同时段仍高度相关，不能称跨场景泛化。真实物理目标标签目前不足。

最终训练主监督是数值幅值配对，不需要作者RGB图像作为目标，也没有把作者RGB整网当作完整教师做等价蒸馏。

## 4. 标签为何设计成增益

训练中：

$$x=\sqrt{P_1/\max P_1},\quad y=\sqrt{P_{\rm ref}/\max P_{\rm ref}},$$
$$s^*=\operatorname{clip}\left(\log_2\frac{y+10^{-5}}{x+10^{-5}},-3,\log_2 1.5\right),$$
$$\widehat y=x\,2^{\operatorname{clip}(s,-3,\log_2 1.5)}.$$

这样网络主要学“这个输入点应当乘多少”，而不是自由生成任意像素。小常数防止零值比值发散，有界头限制极端修改。

注意参考与输入分别按自己的峰值归一化；输出评价沿用输入峰值尺度，不再把输出独立拉满。这能避免“每张图重新拉伸”掩盖整体压暗，但也意味着目前没有绝对功率标定。

## 5. 完整损失分别想解决什么问题

代码使用复合经验损失，不只是普通MSE：

| 分量 | 系数/形式 | 目的 |
|---|---|---|
| log2增益SmoothL1 | 0.35；对有效非极小输入加权 | 直接教输出头接近理想增益 |
| 对数幅值误差 | 0.2；比较log(1+幅值/0.001) | 弱幅值也能影响训练 |
| 幅值平方误差 | 20 | 保持主要重建结构 |
| 支持区域比旁路变差惩罚 | 4；允许0.002误差余量 | 减少恢复反而伤害参考支持峰 |
| 中心/已知目标相对误差惩罚 | 2 | 避免全局均值掩盖少量目标损失 |
| 伪影过估计惩罚 | 0.3 | 约束超出参考的伪影残留 |
| 低背景增益大于1惩罚 | 0.1 | 避免背景被无意义放大 |
| 特别目标保护 | 20；相对误差退化与0.52参考半幅保护 | 针对有支持峰的误压制 |

基础像素权重为1+3S+5K+8C，S为参考派生的支持区域，K为受控数据已知目标区域，C为参考较强局部峰；其它分量采用各自掩码和归一化。最后特别保护分量使用clip(C+K,0,1)。实际分母、ReLU和余量以匹配快照为准，不能把上表重新拼成另一个“等价实现”。

这些参考掩码用于训练，部署保护则只看输入功率与特征。不要混淆成“上板也知道真实目标位置”。

## 6. 定点化究竟是什么

Qn表示小数部分有n位，例如Q14整数16384表示1.0。Q16不等于整个数只占16位。

| 数据 | 当前表示 |
|---|---|
| 外部基础特征 | Q12，13位无符号容器，含4096=1 |
| 内部展开特征/激活 | Q16，32位有符号 |
| 权重 | Q16，20位有符号；不能称纯INT16网络 |
| 偏置 | Q32缩放，使用足够宽的整数存储 |
| 乘加累加器 | 48位有符号 |
| 输出分数查表 | 分数量化到Q10，exp2查表 |
| 最终幅值增益 | Q14 |
| 原始及输出功率 | uint64，乘法使用扩展位宽，最终饱和 |

一层主要计算：

$$a_{\rm next}=\operatorname{roundshift}_{16}(W_{\rm Q16}a_{\rm Q16}+b_{\rm Q32}).$$

中间加法与乘法必须有足够位宽，不能先在窄位宽溢出再扩位。已有区间界检查对全部允许特征范围给出累加器界，部署使用48位保留余量。已有PC数值检查的浮点/定点增益最大差约0.00327，这是检查样本上的结果，不是所有未知输入的全域误差定理。

已有3整帧含uint64极值、全零帧及RTL向量检查，证明所测实现与参考一致。它们不证明恢复质量一定优于旁路。

## 7. IP在系统里实际放在哪里

网络以AXI主接口访问FFT功率DDR缓存，不是接一根AXI-Stream线后立即输出RGB的流式模块。

| 缓存 | 地址/大小 | 用途 |
|---|---|---|
| AQ/AR | 0x23000000起 | 原插值几何映射参数 |
| FFT功率 | 0x24000000–0x243FFFFF，4MiB | 网络输入及最终写回 |
| 两个显示缓存 | 0x25000000、0x26000000 | 原显示链路 |
| 原始SD DMA环 | 0x28000000–0x2FFFFFFF，128MiB | 64×2MiB原始块 |
| 网络工作区 | 0x31000000–0x31FFFFFF，16MiB | z、统计、score/增益、门控支持 |

PC使用自然Doppler顺序，板端功率列shift了256。HLS读取和写回均使用a^256转换；如果忽略这点，谐波关联位置会查错。

HLS先完成整帧峰值/特征/增益，再统一乘g²写回，防止后面的邻域特征读到前面已经改过的数据。

### 为什么BD图上看起来网络控制模块在FFT前

network_frame_control负责决定当前输入帧是否准入，会放在进入FFT之前；它透传的是I/Q流。image_preprocess也在FFT前，负责符号量化。

真正执行神经计算的scalar_gain通过AXI读取FFT完成后的功率缓存。因此“控制器在FFT前”和“数值网络在FFT后”可以同时成立，不能只凭一个模块的图形位置判断计算顺序。

控制时序是：

1. 接纳一个完整成像帧，FFT计算并写功率缓存。
2. fft_done后启动网络。
3. net_done后启动原插值。
4. interp_done后释放该帧。

忙时整帧跳过成像输入；原始SD分支独立接收。它不是将所有成像帧排队等待处理，也不是保证2Hz输入全部经网络。
